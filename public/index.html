WhyNotShare Info

What is WhyNotShare?
WhyNotShare is a zero-installation, browser-native P2P sharing suite. Connect phones, laptops, or tablets over local Wi-Fi or the open internet with no cloud storage, tracking, or user accounts — data flows directly device-to-device over WebRTC.
P2P File Transfer: Chunked streaming (64KB segments) handles multi-gigabyte files without freezing the browser or exhausting memory.
AES-256 E2E: End-to-end encrypted chat and file transfer, powered by the native Web Crypto API.
Host Governance: Room creator gets privileged control: rotate encryption keys and toggle E2E / Plaintext mode live.
Hash-Routed Rooms: Room codes and secret phrases live only in the URL hash fragment — never sent to any server.
100% Open Source • Built with zero tracking or telemetry.

Signaling & Relay
WEBRTC HANDSHAKE
WebRTC needs a brief handshake to exchange connection info (ICE candidates) before peers can talk directly. WhyNotShare supports two signaling paths:
•
Public relay (default): A PeerJS-based signaling broker (0.peerjs.com) is used only for the initial 1–2 second handshake. No file, chat, or media data ever passes through it — once peers are paired, everything moves directly over the encrypted WebRTC data channel.
•
Local fallback (npm start): For offline LANs or environments where external signaling isn't allowed, run the bundled Node.js server (server.js). It reads your machine's local network interfaces just to print your LAN address (e.g. http://192.168.1.X:7890) to your terminal — this address is never logged to disk, sent externally, or committed anywhere.

Zero-Knowledge Encryption (AES-GCM 256-bit)
All payloads — chat messages and file chunks alike — are encrypted client-side before they ever touch the network, using the browser's native crypto.subtle API:
•
Key derivation: Your passphrase is run through PBKDF2 (SHA-256, 100,000 iterations) with a cryptographic salt to produce a 256-bit symmetric key.
•
Encryption: Every message and every 64KB file chunk gets its own random 12-byte IV and is sealed with AES-GCM, producing a 16-byte authentication tag.
•
Tamper detection: If a chunk is altered or corrupted in transit, GCM authentication fails and the packet is silently discarded before it ever reaches reassembly.
Keys are derived and held only in browser memory — they are never transmitted, logged, or stored server-side.
Room Control Guide
•
Host Governance: The room creator can rotate the encryption passphrase at any time (auto-generated or custom) and switch the whole room between End-to-End Encrypted and Plaintext mode — all peers update instantly without dropping their connection.
•
Lock Room & Kick Peers: Lock room access from new members or kick unwanted peers anytime from the host governance drawer.
•
Media & Batch ZIP: Preview shared images/videos full-screen with click-to-zoom and one-key Esc navigation, or download shared files as a `.zip` archive.
•
Device Awareness: Peers are shown with icons identifying their OS (Android/iOS/macOS/Windows/Linux) and browser, so you always know who's in the room.
•
QR Code & Copy Link: Share the room instantly via a vector SVG QR code or a copyable hash-routed link.
